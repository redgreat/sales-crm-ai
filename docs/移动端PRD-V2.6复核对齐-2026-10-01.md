## 2. 产品版新增的 AI 侧相关要求（此前清单未覆盖）

1. **M19 三类意图分流**：查询类（检索+权限过滤+出处）、动作类（建任务/设提醒/记沟通→草稿确认）、新增补增类（识别归属→引导追问→草稿确认）——「三类都不直接改数据」。与 AI 侧「候选仅建议输出」红线一致，无冲突。
2. **M19 主管常用**：给成员派任务、约会议——动作类草稿，映射现有候选机制，不新增 AI 能力类型。
3. **M15 拜访 AI 总结**：签退（用户主动动作）→ 触发生成纪要草稿 + 待办草稿（S2）；真实性验证结果仅作附注。符合「不因事件默认启动自动 AI 流程」精神（签退即主动请求，产物必为草稿）。
4. **M16 语音补充日报**：语音 → ASR → 文本进草稿编辑，属增强输入 POC 链（需求 4.12），适配层已就绪待凭据。
5. **M01 今日任务总结**：对应需求 4.10 今日任务（已实现的 analysis 图），底单由 CRM 确定性规则装配，AI 只做归纳——与现有 `requires_facts` 契约一致。

## 4. M-03 扩范围的 AI 侧落实路径（不在本轮实现）

产品版把「对话建档」写入一期并配齐红线（查重/必填追问/权限内/留痕），等于给出了 09-30 要求的「单独变更单」的实质内容。若确认按 6 项能力推进：

1. **前置**：P4 冻结 CRM 侧建档接口（客户/联系人/线索/商机 Service + 查重接口）；AI 不写正式表，仍只产草稿候选，由 CRM 确认后写入。
2. **AI 侧改动**（P4 后）：注册表新增 4 个写草稿能力 + 2 个查询能力（`read_only=false` 的候选型 + `read_only=true` 的查询型）；能力目录端点自动透出；fact_guard/候选机制原样复用。
3. **不因 M-03 阻塞当前链路**：M03/M15/M25 文字与候选核心链（活动/任务）不依赖建档能力，P4 照常推进。

## 5. 本轮 AI 侧代码收口（P3 会话多轮，无需产品确认）

修复实施计划 P3 登记的缺口，全部真实 PostgreSQL 测试：

1. **消息窗口语义修复**：`list_messages` 原实现 `ORDER BY seq LIMIT` 取的是**最早** N 条——长会话里历史装配会丢掉全部近期上下文。改为最近 N 条（子查询 DESC 后反转为正序）；`GET /messages` 暴露 `limit`（≤500）与 `before_seq` 翻页参数。
2. **每轮独立 Run（实质缺陷）**：`post_message` 原默认幂等键为固定 `conv:{id}:{user}`——同一会话第二条消息会**重放第一个 Run**，多轮对话只有第一轮真正执行。改为：客户端提供幂等键则命名空间化采用（`msg:{conversation_id}:{key}`，同 key 重试幂等重放原 Run）；未提供则一次性键（每条消息独立 Run）。
3. **消息级幂等（M-07）**：迁移 `0004_conversation_expiry.sql` 给 `ai_messages` 加 `client_key` 列与同会话唯一索引；重复提交（同 key）在落库层去重，不产生重复消息或重复 Run；补参应答重试同样幂等。
4. **会话 TTL 过期**：`ai_conversations.status` 增加 `expired`；`expire_stale_conversations(ttl_hours)` 清理超时无活动会话（默认 72h，`conversations.ttl_hours` 可配，0=禁用）；消息活动刷新会话 `updated_at`；worker 循环低频（10 分钟）扫描。**M-01 红线**：过期只影响「能否续问」，绝不改变候选业务状态（已测）。
5. **生命周期入口一致性**：closed/expired 会话在 `post_message`、`create_run`（带 conversation_id）、`resume` 三个入口一致拒绝（此前 create_run/resume 不校验会话状态）。
6. **checkpoint 撤权复核结论（无需新代码）**：qa 族图（object/business/knowledge.qa、meeting.prepare）持有 `knowledge_facts`/history 但**无 interrupt 节点**（每轮全新 invoke、executor 每轮重新装配并过滤）；extract 图会 interrupt 但 checkpoint 不含知识/历史材料。当前图拓扑下「旧 checkpoint 借道恢复无权材料」无暴露面；若将来 qa 族加补参 interrupt，须在 resume 前对 checkpoint 里的 knowledge_facts 按当前授权重过滤——已记入实施计划 P3 说明。
7. **顺带修复**：`app/persistence/conversations.py` 的 `isinstance(source, psycopg.AsyncConnectionPool)` 运行时必然 `AttributeError`（`AsyncConnectionPool` 在 `psycopg_pool` 包），会话多轮 API 全链路因此崩溃——该缺陷此前未被测试捕获（import 被自动清理后引入）。
