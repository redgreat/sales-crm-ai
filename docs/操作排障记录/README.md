# 操作排障记录（写法规范）

本目录只记录**对仓库里代码 / 配置 / 文件的实际改动**（含新建、删除文件），方便出问题时按时间回查「谁、何时、改了哪些路径、结果如何」。

- 计划与验收口径 → `docs/AI接入实施计划.md`
- 怎么跑测试、用哪个账号 → `docs/测试规范.md`
- 待确认事项 → `docs/开放项待确认清单.md`
- **改了哪些文件** → 本目录当月卷

聊天里的讲解、目录梳理、概念对比、只读排查、只跑命令而未改仓库的内容，**一律不记**。

对人工与任何 AI 均适用。动手写月卷前先读完本 README。

---

## 1. 文件怎么放

```text
docs/操作排障记录/
  README.md          # 本文件：字段与红线（只改规范，不记流水）
  YYYY-MM.md         # 当月操作卷，例如 2026-10.md
```

- 新的一个月：新建 `YYYY-MM.md`，文件头复制下方「月卷模板」。
- 不要把流水写进 README；不要把密钥写进任何文件。

---

## 2. 记什么、不记什么

**要记（必须有仓库路径变化）：**

- 新增 / 修改 / 删除源码、配置、文档、脚本、测试文件
- 后台或 `conf/` 里改了会进仓库或会进配置文件的项（密钥值本身不写进记录）

**不记：**

- 口头/聊天说明（例如「tests 分几档」「流式和思考什么关系」）
- 只读代码、只搜索、只看文档
- 只跑 pytest / 脚本 / 服务、没有改任何文件
- 纯环境结论（本机没有 initdb 等），除非同时改了仓库里的文件

一条记录的「操作」列必须能列出**路径**（文件或目录）。列不出路径就不要写这一行。

---

## 3. 操作者身份

每条 **操作者** 只能填下列之一（不要写「我们」）：

| 取值 | 含义 |
|---|---|
| `人工` | 人在本机改了文件（含按 AI 提示手工改） |
| `AI` | 当前对话里的 AI 直接改了仓库文件 |
| `CI` | 流水线改了仓库（少见；一般流水线不写本目录） |

**会话**：短标签，区分并行 Agent，例如 `2026-10-10-crm-ai入门`。不要写密钥、JWT、`api_key`。

---

## 4. 任何 AI 的写入红线（强制，与模型无关）

打开月卷（或 README）时，**当时已经存在的全部文字视为冻结原文**。

| 允许 | 禁止 |
|---|---|
| 在文件**末尾**（当天主表最后一行之后、当天节末尾）**追加**本会话新条目 | 改、删、重排、润色**打开时已经存在**的任何一字 |
| 仅删除或改正：**本会话在打开文件之后自己追加的、且确认记错**的那几行 | 改其他 AI、其他人、或自己**上一会话**已经落盘的内容 |
| 人工**明确要求**修改本 README 规范时，才改 README | 为「格式统一」去动历史表；把新行插进旧日期中间 |

细则：

1. **打开时原文不可改。** 无论哪个产品、哪个模型，都不得改打开文件时已有的标题、表格行、段落、标点、空白。
2. **只能动自己刚生成的内容。** 「自己」= 当前这一次对话里、打开文件之后新写上去的行。不是「同一个文件夹里凡是 AI 写的都能改」。
3. **发现旧条目有误：** 不要改旧行；在末尾**追加**一行「更正」，写清指向哪条时间。
4. **隔日或文件已被他人打开过：** 本会话先前写入的内容也变成「打开时原文」，下一轮 AI 不得再改，只能再追加。
5. 违反 = 不合格。应把文件恢复到打开时的内容，再只做追加。

用一句话：**AI 对月卷是只追加；唯一例外是删掉自己在本轮打开之后写错的新行。**

---

## 5. 每条必填字段

一行一事。主表列：

| 列名 | 必填 | 说明 |
|---|---|---|
| 时间 | 是 | 本地时区到分钟：`YYYY-MM-DD HH:mm` |
| 操作者 | 是 | `人工` / `AI` / `CI` |
| 会话 | 否 | 短标签 |
| 目的 | 是 | 为什么改这些文件（一句话） |
| 操作 | 是 | **列出改动路径**（新增/修改/删除）；不要贴密钥 |
| 预期 | 是 | 改完后应怎样 |
| 结果 | 是 | `通过` / `失败` / `跳过` / `部分` + 极短说明 |
| 证据与下一步 | 是 | 验证命令或关键报错一句（无密钥） |

---

## 6. 月卷写法

1. 当天用 `## YYYY-MM-DD`；先主表，复杂改动再在表下加 `### HH:mm 标题`（只列路径和验证，不写教程）。
2. 新条目只加在**当天主表最后一行之后**，或当天节末尾。
3. 连续多步改文件：多行、时间递增；不要把无关改动合成一行。

### 主表示例

```markdown
## 2026-10-10

| 时间 | 操作者 | 会话 | 目的 | 操作 | 预期 | 结果 | 证据与下一步 |
|---|---|---|---|---|---|---|---|
| 2026-10-10 09:13 | AI | 2026-10-10-思考开关 | 默认关闭百炼思考并真正传参 | 改 `app/config.py`、`app/providers/factory.py`、`conf/config.yml.example`、`app/admin/schema.py`、`tests/test_providers.py` | `extra_body` 含 `enable_thinking: false` | 通过 | pytest 2 passed |
```

### 细节小节示例（可选）

```markdown
### 09:13 关闭百炼思考接线

- 改动：`app/config.py`、`app/providers/factory.py`、`conf/config.yml.example`、`app/admin/schema.py`、`tests/test_providers.py`
- 验证：`pytest tests/test_providers.py::test_openai_compatible_defaults_enable_thinking_false -q`
- 结果：通过
```

---

## 7. 禁止写入的内容

- 任何 `api_key`、`service_secret`、JWT、密码、bootstrap 口令全文
- 讲解性长文、测试分层说明、概念对比
- 大段终端日志（最多一行错误信息）
- 未改文件却声称「已操作」

---

## 8. 月卷文件头模板

新建 `YYYY-MM.md` 时用：

```markdown
# 操作排障记录 · YYYY-MM

> 写法见 [README.md](./README.md)。打开时已有正文冻结。任何 AI 只可在末尾追加本会话改动；只可删除本轮打开之后自己写错的新行。

## 当月速览（可选）

| 日期 | 摘要 |
|---|---|
| YYYY-MM-DD | 一句话（仅文件改动） |

## YYYY-MM-DD

| 时间 | 操作者 | 会话 | 目的 | 操作 | 预期 | 结果 | 证据与下一步 |
|---|---|---|---|---|---|---|---|
```
