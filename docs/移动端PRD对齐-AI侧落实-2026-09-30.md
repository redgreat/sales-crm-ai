> 输入：`docs/移动端PRD对齐建议-2026-09-29.md`（M-01～M-12）。
> 范围：只改 `sales-crm-ai`。移动端原型、后端 PRD 不在本文改动范围。
> 原则：**阻断项按后端口径落实**；"待确认"不自动进入一期；AI 不替产品合并冲突。

## 2. 已修正项（代码变更）

### M-10 知识：三条硬要求

1. **只检索已发布当前版本**
   - 缺陷：原实现按 `version DESC` 选"最新"，而 `version` 是 TEXT，字符串序会让 `v10` < `v9`，**选到旧版本**。
   - 修正：迁移 `0003_knowledge_current.sql` 增加 `is_current`；检索排序改为
     `is_current DESC, published_at DESC NULLS LAST, created_at DESC`。当前版本由 CRM 发布时声明，AI 不猜。
   - CRM 未标记 `is_current` 时退化为发布时间序（兼容），补齐标记后自动恢复严格语义。

2. **角色×业务线组合不在 AI 侧计算**
   - 修正：`validate_scope` 只接受 `public` / `users`；出现 `roles`、`biz_lines`、`depts` 等组织维度
     **一律拒绝同步**（失败即关闭）。避免"角色 A 或业务线 B"被 AI 自行取并集放大为两者皆可见。
   - 交集还是并集由 CRM 展开为具体 `user_id` 后决定，AI 不理解组织结构。

3. **撤权后不得再次进入模型**
   - 缺陷：撤权只让知识从**检索集合**消失；但历史会话里引用过该知识的旧回答会作为 `[H]` 行
     原样送入模型——**撤权内容借历史绕回来了**。
   - 修正：助手消息落库时记录 `meta.knowledge_refs`；加载历史前调用
     `filter_unauthorized_history` 剔除引用已撤权/已无权知识的旧回答（只剔 assistant 消息）。

### M-12 能力入口

新增 `GET /api/v1/capabilities`（及 `/{capability}`），由注册表渲染，返回：
`capability`（能力码）、`read_only`（只读标识）、`graph_version`/`prompt_version`、
`context_required`（当前上下文）、`entry_conditions`（可见条件）、`return_path`（源对象返回路径）。

此前前端只能硬编码按钮，注册表一变就漂移成"页面有按钮但调用必失败"。现在能力增删只改注册表一处。

### M-01 候选不得作为事实

新增 `app/graphs/fact_guard.py`：事实行若带 `type ∈ {candidate, ai_candidate, draft, ...}`、
`confirmed=false`、或 `status ∈ {pending, 待确认, 未确认, ...}`，只读分析与问答图**直接失败**，不送模型。

这是纵深防御——事实本由 CRM 装配，但若装配侧误把候选塞进 `facts`，这里会失败而不是让
"AI 用自己未确认的猜测给自己作证"。

## 2.1 顺带修的一个质量缺陷（不在 M 清单内）

**知识检索不看问题内容**：`knowledge.qa` 原本注入的是"最近 5 条有权文档"，
与用户问的是什么无关——问报销可能拿招聘制度当依据。

- 修正：`search_authorized` 新增 `query` 参数，先取更大候选池再按字面相关度重排
  （CJK 二元切分 + 拉丁词，标题命中权重高于正文）。
- 边界：相关性**只用于排序，不参与授权判定**——无权文档在 SQL 层已排除，
  不会因为"相关"被放行；全部零命中时保持原序，不假装检索到相关文档。
- 未引入向量/外部依赖，纯标准库实现。

## 3. 明确不做的（避免暗自扩范围）

- **M-02 批量确认 / 追踪任务派生**：确认、写入、部分成功重试都在 CRM 侧（后端 05 §8～9）。
  AI 只产出候选建议，**不派生任何"追踪任务"**，也不提供批量确认接口。
- **M-03 对话建档**：一期能力只有沟通整理、摘要/问答、知识、会前准备、日报。
  新增客户/联系人/线索/商机建档需单独变更单与权限/查重/证据设计。
- **M-04 自动采集**：ASR/OCR 适配层已就绪但默认关闭，且只服务**用户主动上传**。
  M24 的"会议结束自动整理纪要"不实现——结束事件不得默认启动未批准的自动 AI 流程。
- **M-08 推送**：AI 无推送、无消息等级、无个人偏好配置。

## 4. 需移动端产品确认（AI 不替其决定）

1. 是否按后端口径取消 24h 自动过期与追踪任务派生（M-01/M-02）？
2. M20 对话建档是否移出本期（M-03）？
3. 工作手机自动采集是否继续排除，M24 改主动上传（M-04）？
4. 知识权限组合与外部转发是否以 08 为准（M-10）？
5. 生产 H5 的实际仓库与登录方式（不要把 Svelte 联调页当移动端完成）。

## 5. 本轮额外推进（无需产品确认即可做）

1. **需求 4.14 普通文件解析**（P5 唯一不受凭据阻塞的剩余项）：`app/integrations/files.py`
   + `POST /api/v1/files/parse`。只支持纯文本类（txt/md/log/csv/json/yaml），
   **docx/pdf/xlsx 显式报错不留假结果**；编码 utf-8→utf-8-sig→gb18030 回退；
   超限截断并标记；批量逐项返回失败原因。测试 `tests/test_p5_file_parsing.py` **16 passed**。
2. **知识检索相关度排序**（见 2.1）。
3. **日报底稿携带 `as_of` / `facts_count`**（M-09"展示截至时间及新事实提示"）。
4. **ASR/OCR 联调手册**：凭据到位后按 `docs/ASR-OCR联调手册.md` 执行即可完成 POC。
