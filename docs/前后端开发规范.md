# 前后端开发规范（sales-crm-ai）

> 2026-10-02 建立。本文件是 **AI 编码的强制约束**，与 `docs/测试规范.md`、`docs/PostgreSQL数据库规范.md` 配套。
> 写 Python 后端看第 2 节，写前端看第 3 节，跨端协作看第 4 节，提交前过第 5 节清单，第 6 节是红线。
> 规范与代码冲突时，以**已通过评审的代码**为准，并在本文件记录分歧。

## 0. 适用范围与仓库边界

| 层 | 仓库 / 目录 | 技术栈 | 本规范对应节 |
|---|---|---|---|
| AI 后端 | `sales-crm-ai/app`（本仓） | Python 3.12 + FastAPI + LangGraph + PostgreSQL | §2 |
| AI 联调前端 | `sales-crm-ai/frontend`（本仓） | SvelteKit 2 + Svelte 5 + TypeScript + Tailwind 4 | §3.1 |

**跨仓铁律**：本仓只改 `app/`、`frontend/`、`conf/`、`scripts/`、`tests/`、`docs/`。
前端业务代码改在 `sales-crm-admin-ui`，CRM 集成薄层改在 `sales-crm-api-service`；
跨仓改动必须先在交接记录里写清**边界、接口版本、影响面**，再动手。

## 1. 通用工程约定

1. **分支与提交**：动工前先 `git branch --show-current` + `git status`，保留他人改动；一个工作包一个提交，信息写「做了什么 / 为什么」。
2. **语言**：代码注释、docstring、日志文案、接口 `message` 一律**简体中文**；标识符、类型名、错误码用英文。
3. **命名**
   - Python：模块/函数/变量 `snake_case`，类 `PascalCase`，常量 `UPPER_SNAKE_CASE`，私有前缀 `_`。
   - 前端：组件文件 `kebab-case`（`result-card.svelte`、`customer-list.vue`），组合式函数/工具 `camelCase`，类型 `PascalCase`。
4. **注释**：解释**为什么**，不解释代码在做什么。禁止注释掉的代码块、禁止 `# TODO` 无责任人。
5. **密钥**：`conf/config.yml` 不入库（只提交 `.example`）；真实密钥走环境变量注入。
   密钥、模型 usage/费用/配额 **不进日志、不进消息体、不进 checkpoint**。
6. **依赖**：改动 `pyproject.toml` / `package.json` 必须同步锁文件（`requirements.lock` / `package-lock.json`），并记录实测版本；禁止 `>=` 宽泛放开核心框架版本。
7. **不做的事**：不自动迁移真实库、不安装全局依赖、不改生产环境、不外发真实业务数据、不擅自发布。

## 2. Python 后端规范（app/）

### 2.1 运行时与分层

- Python **≥ 3.12**；依赖锁定见 `pyproject.toml`（FastAPI 0.141.1 / pydantic 2.13.4 / langgraph 1.2.11 / psycopg 3.3.4）。
- 分层与依赖方向**单向**，不得反向 import：

```
app/api          HTTP 入口：路由、依赖注入、异常处理器
  └─ app/runtime     执行器、worker 循环、租约与幂等
       └─ app/graphs     LangGraph 图、节点、状态、中断
            └─ app/integrations  外部系统适配（CRM / OSS / OCR / ASR）
            └─ app/knowledge     知识库检索
            └─ app/providers     模型 Provider 工厂
app/persistence  连接池、checkpoint、会话、运行记录、nonce、迁移
app/{config,auth,errors,capabilities}  横切基础设施
```

- `app/api/routes/` 只做参数校验 + 编排 + 转错误码，**不写业务逻辑、不写 SQL**。
- 新增能力（capability）走 `app/graphs/builder.py` 注册表，禁止在路由里 `if capability == ...` 硬分叉。

### 2.2 编码风格

- 每个模块首行写**中文模块 docstring**，说明职责与不变量（参照 `app/api/main.py`、`app/config.py`）。
- 所有公开函数/类带完整类型注解；文件头统一 `from __future__ import annotations`，用 `X | None`、`dict[str, Any]` 新语法。
- 导入顺序：`__future__` → 标准库 → 第三方 → `app.*` 本地（绝对导入，禁止相对导入跨包）。
- 不用 `Any` 偷懒：跨模块传递的业务对象用 `pydantic.BaseModel` 或 `TypedDict` 显式建模。
- 异步边界清晰：I/O 用 `async/await`，CPU 密集不放事件循环；worker 与请求路径分离。
- 禁止裸 `except:`；至少要 `except SpecificError`，且必须记录或向上抛 `ApiError` 子类。

### 2.3 配置

- 唯一入口 `app/config.py::Settings`（pydantic-settings + YAML）。查找顺序：显式路径 > `SAI_CONFIG` > `./conf/config.yml` > 项目根 `conf/config.yml`。
- 新增配置项**必须**同时改 `conf/config.yml.example`，并在 `Settings` 里给类型与默认值。
- 禁止在业务代码里 `os.getenv` 散取配置；禁止把密钥写进默认值。

### 2.4 错误契约

- 业务错误一律抛 `app/errors.py` 的 `ApiError` 子类（`Unauthenticated/Forbidden/NotFound/Conflict/...`），
  统一响应体：`{"error": {"code": "...", "message": "...", "details": {...}}}`。
- 禁止直接 `raise HTTPException` 或返回裸字符串；未捕获异常由全局 handler 转 500 并记录 `logger.exception`。
- `details` 只放**可对外**的结构化信息，绝不回填上游原始报文、密钥、SQL。

### 2.5 接口路由

- 路由前缀 `/api/v1/...`，健康检查 `/health` 与就绪 `/ready` **分离**：启动只校验不改库，checkpoint/迁移未就绪时 `/ready` 失败且**不降级无状态模式**。
- 每个请求**逐轮重新鉴权**：服务间 HMAC（`key_id` + 时间戳窗口 + nonce 防重放）或 CRM JWT，二选一按接口约定，不能只验一次。
- 列表接口必须有分页与上限；写接口必须支持幂等键；长任务返回 `run_id` 由客户端轮询，不让 HTTP 请求挂等到超时。
- 请求/响应模型用 pydantic 显式声明，禁止 `dict` 透传裸 JSON。

### 2.6 持久化

- AI 自有库 `zrcrm_ai`：表结构变更走 `app/persistence/migrations/versions/`，**显式执行**（`python scripts/init_db.py --apply`），启动脚本不得自动改库。
- 连接池统一从 `app/persistence/pool.py` 取，禁止各模块自建连接；用参数化查询，禁止字符串拼接 SQL。
- **禁止直连 CRM 主库** `zrcrm`；CRM 数据只经授权接口，CRM 库的表/字段约定参见 `docs/PostgreSQL数据库规范.md`。
- checkpoint 只做执行状态恢复，**不代替**执行租约、用户授权、业务幂等；必须覆盖重启恢复、旧执行者迟到、重复 resume、历史撤权、部分成功场景。

### 2.7 日志与可观测

- 用模块级 `logger = logging.getLogger("sales-crm-ai")`，禁止 `print` 输出运行信息。
- 结构化关键字段：request_id、run_id、capability、staff_id；**不记录**模型 prompt 全文外的密钥、不记录 usage/费用。
- 供应商 usage **不落日志/消息/checkpoint**。

### 2.8 测试

- `pytest`，`asyncio_mode = "auto"`，测试放 `tests/`，命名 `test_*.py`。
- 先写失败测试再实现；交接必须给出**测试命令 + 结果 + 阻塞 + 下一步**。
- 需要真实 PostgreSQL 的用例打 `@pytest.mark.realpg`；缺依赖显式 skip，**不得静默降级为内存/无状态**。
- Stub 模型、真实模型、正式 CRM 验收三类结果**明确区分**，缺凭据不得声称通过。

## 3. 前端规范

### 3.1 A. AI 联调前端（本仓 `frontend/`，SvelteKit 2 + Svelte 5）

- **技术栈锁定**：Svelte 5（runes 语法）、SvelteKit 2、Vite、TypeScript `strict: true`、Tailwind 4、`bits-ui` 组件。
- 目录：`src/routes/` 页面、`src/lib/components/` 组件（kebab-case）、`src/lib/api.ts` 唯一接口出口、`src/lib/utils.ts` 纯函数。
- 类型：所有 API 出入参在 `src/lib/api.ts` 里定义 `interface`/`type`；禁止 `any`，解析失败要有兜底分支。
- 请求：统一走 `src/lib/api.ts` 的 `request<T>()`，基址 `/playground/api` 同源代理；
  **浏览器不持任何密钥**（开发代理在服务端签名注入联调身份，生产由 CRM 同源集成接口替代）。
- 错误：沿用后端 `ApiError(code, message, status)`，UI 展示 `message`，`code` 用于分支；网络失败要给可重试提示。
- 提交前跑 `npm run check`（svelte-check）；组件不写内联大段样式，复用 Tailwind 工具类。
- 本前端现为**开发环境配置后台**（5174）：只编辑非密钥配置，写入忽略文件 `conf/config.ui.yml`，重启后生效；生产默认关闭，不得作为正式业务入口。业务联调使用 `tests/h5/`。

### 3.2 B. CRM 业务前端（`sales-crm-admin-ui`，Vue 2 + element-ui 2）

> 本仓不直接改它，但 AI 涉及前端方案设计、接口约定、评审时必须遵守以下约定。

- **技术栈锁定**：Vue 2 + vue-cli + element-ui 2 + Vuex + vue-router + axios。**不得引入 Vue 3 / 模板仓的 Vue3 管理门户**。
- 目录：`src/views/<模块>/` 页面、`src/components/` 公共组件、`src/api/<模块>.js` 接口层、`src/store/` 状态、`src/router/` 路由。
- 接口层：每个业务模块一个 `src/api/*.js`，统一 `import request from '@/utils/request'`，导出具名函数：
  ```js
  export function customerMeta() {
    return request({ url: '/api/v1/salescrm/customers/meta', method: 'get' })
  }
  ```
  URL 前缀固定 `/api/v1/salescrm/`；查询用 `params`，提交用 `data`。
- 代码风格（Prettier，见 `prettier.config.js`）：**2 空格缩进、单引号、无分号、箭头参数带括号、行宽 140、LF 换行、对象花括号留空格**。
- ESLint（`plugin:vue/recommended` + `@vue/prettier`）：
  模板中组件名必须 **kebab-case**；属性顺序遵循 `vue/attributes-order`（定义 → 列表渲染 → 条件 → 双向绑定 → 事件）；
  组件选项顺序遵循 `vue/order-in-components`（name → components → props → data → computed → watch → 生命周期 → methods）。
- 权限：页面/按钮受**按钮权限**控制，列表/详情受**数据权限**控制（见 `sales-crm-api-service/docs/用户中心按钮权限.md`、`项目数据权限总览.md`）；
  前端隐藏**不等于**后端放行，后端必须独立校验。
- 禁止：在组件里散写 axios 调用、硬编码接口地址、把后端原始错误直接 toast 给用户、用 `v-html` 渲染外部输入。

## 4. 前后端协作契约

1. **接口先行**：新增/修改接口先定请求-响应模型与错误码，再并行开发；字段名一律 `snake_case`，时间用 ISO 8601 字符串，金额/比率明确单位与精度。
2. **错误码一致**：后端 `ApiError.code` 是前后端唯一判断依据，UI 文案由前端映射，**不直接回显后端 message 原文给用户**。
3. **长任务**：后端返回 `run_id` + 状态机（`queued/running/waiting_input/succeeded/failed/cancelled`），前端轮询并在 `waiting_input` 时渲染补参表单；补参**不等于**正式写入授权。
4. **会话语义**：会话历史、窗口记忆、结构化补参三者分开存；每轮重新鉴权。
5. **版本记录**：跨仓接口变更必须在交接说明里写「接口路径 + 版本 + 兼容性（是否破坏旧前端）」。
6. **AI 不越权写入**：候选数据需本人确认，正式活动/任务/日报/知识主档由 CRM 正式 Service 写入；AI 侧只产出候选。

## 6. 红线（一律禁止）

1. 直连或改动 CRM 主库 `zrcrm`；绕过授权接口读写 CRM 业务数据。
2. 自动迁移真实库、启动脚本改库、在 `lifespan` 里执行 DDL。
3. 把密钥、模型 usage/费用/配额写进日志、消息体或 checkpoint。
4. 静默降级：checkpoint/模型/CRM 不可用时假装可用（无状态图、假成功、缺凭据称通过）。
5. 把 AI 联调前端当生产入口；复制模板仓的 Vue3 管理门户。
6. 删除或绕过服务认证与 CRM 权限校验。
7. 擅自发布、删除远端分支、购买服务、外发真实业务数据。
